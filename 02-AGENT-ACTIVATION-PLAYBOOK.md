## 1. PROJECT TYPE CLASSIFICATION

Before activating agents, classify the incoming project:

```
PROJECT CLASSIFICATION MATRIX
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

TYPE A: Full-Stack Web Application
  → Client needs a complete web app (frontend + backend + database + infra)
  → Duration: 3-9 months | Team: 8-20 agents | Budget: $200K-$2M

TYPE B: Mobile Application
  → Client needs iOS/Android app (with optional backend)
  → Duration: 3-6 months | Team: 6-15 agents | Budget: $150K-$1M

TYPE C: AI/ML Product
  → Client needs AI-powered features, LLM integration, or data platform
  → Duration: 2-6 months | Team: 6-15 agents | Budget: $200K-$1.5M

TYPE D: API / Platform / Integration
  → Client needs API development, third-party integrations, or platform work
  → Duration: 2-4 months | Team: 5-10 agents | Budget: $100K-$500K

TYPE E: Data Engineering / Analytics
  → Client needs data pipelines, warehousing, BI dashboards, or analytics
  → Duration: 2-4 months | Team: 4-8 agents | Budget: $100K-$400K

TYPE F: Design Sprint / UX Overhaul
  → Client needs UX research, redesign, or design system creation
  → Duration: 1-3 months | Team: 4-8 agents | Budget: $50K-$200K

TYPE G: Security Audit / Compliance
  → Client needs security assessment, pen testing, or compliance work
  → Duration: 2-6 weeks | Team: 3-6 agents | Budget: $50K-$150K

TYPE H: Maintenance / Enhancement
  → Existing client needs ongoing maintenance, bug fixes, or small features
  → Duration: Ongoing | Team: 2-5 agents | Budget: $10K-$50K/month

TYPE I: Proof of Concept (POC)
  → Quick prototype to validate an idea before full engagement
  → Duration: 2-4 weeks | Team: 2-4 agents | Budget: $20K-$80K

TYPE X: Multi-Discipline Enterprise Program
  → Large enterprise engagement combining multiple project types
  → Duration: 6-18 months | Team: 20-50 agents | Budget: $1M-$10M+
```

## 2. ACTIVATION TIERS

Every project activates agents in 4 tiers:

```
TIER 1 — ALWAYS ACTIVE (Background)
  These agents monitor all projects passively:
  ┌─────────────────────────────────────────┐
  │ 188 NEXUS-ORCHESTRATOR — System health  │
  │ 001 CEO — Strategic oversight           │
  │ 004 COO — Operational oversight         │
  │ 005 CFO — Financial monitoring          │
  │ 186 RETRO-AGENT — Learning capture      │
  └─────────────────────────────────────────┘

TIER 2 — LIFECYCLE AGENTS (Activate per stage)
  These agents activate at specific project stages:
  ┌─────────────────────────────────────────┐
  │ 181 DISC-AGENT — Discovery stage        │
  │ 182 EST-AGENT — Estimation stage        │
  │ 176 ARB-AGENT — Architecture stage      │
  │ 177 QA-GATE — Development/QA stages     │
  │ 178 SEC-REVIEW — Security checkpoints   │
  │ 179 REL-APPROVE — Pre-production        │
  │ 180 CHANGE-MGR — Deployment             │
  │ 183 HANDOFF-AGENT — Transition          │
  │ 184 MAINT-AGENT — Post-delivery         │
  └─────────────────────────────────────────┘

TIER 3 — MANAGEMENT LAYER (Activate per project type)
  Directors and managers assigned based on project scope.

TIER 4 — EXECUTION LAYER (Activate per project type)
  ICs assigned based on project requirements.
```

## 4. ACTIVATION PROTOCOL

```
STEP 1: CLASSIFY
  → NEXUS-ORCHESTRATOR (195) classifies project type (A-X)
  → Validated by COO (004)

STEP 2: SIZE
  → EST-AGENT (188) determines team size based on scope
  → Choose MVT, Recommended, or Full team

STEP 3: ALLOCATE
  → COO (004) + SVP-ENG (012) check resource availability
  → Resolve conflicts with existing project allocations

STEP 4: ACTIVATE
  → ONBOARD-AGENT (194) initializes assigned agents
  → Each agent receives: project brief, their role, interaction partners, timeline

STEP 5: VERIFY
  → TPM (176) confirms all required agents are active
  → First team standup within 48 hours of activation

STEP 6: MONITOR
  → NEXUS-ORCHESTRATOR (195) tracks activation health
  → Flags: missing agents, overloaded agents, communication gaps
```

---

## 5. DEACTIVATION PROTOCOL

```
When agents complete their project involvement:

1. HANDOFF-AGENT (190) confirms all deliverables transferred
2. Agent documents lessons learned → RETRO-AGENT (193)
3. Agent updates status to "available" in NEXUS-ORCHESTRATOR
4. NEXUS-ORCHESTRATOR reallocates to next priority project

STICKY AGENTS (remain after main project):
- MAINT-AGENT (191) — ongoing
- TAM (139) — ongoing
- CSM (138) / SR-CSM (137) — ongoing
- SUPPORT-T1/T2 (140/139) — ongoing
```
