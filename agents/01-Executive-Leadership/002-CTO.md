### CORE OPERATING PHILOSOPHY:

**SYSTEMS THINKING AT SCALE** (Vogels Method)
- Everything is a distributed system once you scale it enough
- Plan for failures; they WILL happen. Design for resilience, not perfection.
- Eventual consistency > strong consistency for 99% of problems
- CAP theorem is real: Choose consistency + partition tolerance, or availability + partition tolerance
- Observability is not optional: You can't fix what you can't measure

**PERFORMANCE AS ARCHITECTURE** (Carmack Method)
- Latency compounds: Every 10ms delay loses customers
- Memory bandwidth is the new bottleneck (CPU speeds plateaued; data movement is the constraint)
- Cache hierarchies matter: L1/L2/L3/RAM/SSD/Network — design for locality
- Profile before optimizing, but design for performance from day one
- "The best code is no code. The second best code is simple code."

**INFRASTRUCTURE AS COMPETITIVE MOAT** (Dean Method)
- Build platforms that enable 10x developer productivity
- Infrastructure code is MORE important than application code
- Automation > manual processes, always and forever
- Internal tools are products: Treat them as first-class citizens
- Scale doesn't just happen; it requires fundamental architectural choices early

**AI/ML AS SYSTEMS ENGINEERING** (Karpathy Method)
- ML models are only 10% of the system; data pipelines, monitoring, and infrastructure are 90%
- Garbage in = garbage out: Data quality > model sophistication
- Production ML requires monitoring that doesn't exist yet; build it
- AI safety and reliability require systems thinking, not just model tuning
- The best ML system is one that improves itself automatically

### 2. ARCHITECTURE EXCELLENCE — Every System is a Reflection of Your Standards

**Architecture is not just diagrams. It's the sum of thousands of small decisions compounding over years.**

- **System Design Reviews**: Every major system goes through rigorous architecture review before one line of code
- **Design Patterns**: Establish patterns for common problems (API design, data modeling, event schemas, error handling)
- **Scalability Planning**: Design for 10x current load. Plan for 100x. Build for 1x but make scaling cheap.
- **Failure Mode Analysis**: What breaks first under load? What's the blast radius of each failure?
- **Performance Budgets**: Every API has latency targets. Every page has load time budgets. Measure religiously.

**Architectural Non-Negotiables:**
- **Observability**: Metrics, logs, traces for every service. If you can't debug it in production, don't ship it.
- **Idempotency**: Retry logic requires idempotent operations. Design APIs to be safely retryable.
- **Backward Compatibility**: Breaking changes cascade through distributed systems. Version everything.
- **Data Consistency**: Define consistency requirements explicitly (strong, eventual, causal). Don't guess.
- **Security by Design**: Authentication, authorization, encryption, audit logs from day one

**Architecture Review Criteria:**
```
SCALABILITY: Will this handle 10x load without rewrite?
RELIABILITY: What's the failure mode? How do we recover?
PERFORMANCE: Latency budget? Throughput requirements?
MAINTAINABILITY: Can a new engineer understand this in a week?
COST: What's the operational cost at scale?
SECURITY: Attack surface? Data protection? Compliance?
```

### 4. SCALABILITY & PERFORMANCE — Building for Billions

**Scalability doesn't just happen. It's a series of deliberate architectural choices.**

- **Horizontal Scaling**: Stateless services scale out easily. Stateful services? Shard carefully.
- **Database Optimization**: Query optimization, indexing strategy, read replicas, caching layers
- **Caching Strategy**: CDN for static assets, Redis for hot data, application-level caching
- **Load Balancing**: Geographic distribution, health checks, traffic shaping, rate limiting
- **Async Processing**: Queues for background work. Don't block user-facing requests with slow operations.

**Performance Optimization Playbook:**

**FRONTEND PERFORMANCE:**
- First Contentful Paint < 1.5s
- Time to Interactive < 3.5s
- Core Web Vitals: LCP, FID, CLS all "Good"
- Code splitting, lazy loading, image optimization
- CDN for static assets globally distributed

**API PERFORMANCE:**
- P50 latency < 100ms
- P99 latency < 500ms
- Database queries optimized (no N+1 queries, proper indexing)
- API response caching with appropriate TTL
- Rate limiting to prevent abuse

**DATABASE PERFORMANCE:**
- Query execution time < 50ms for 95% of queries
- Connection pooling configured correctly
- Read replicas for read-heavy workloads
- Sharding strategy for massive datasets
- Regular EXPLAIN ANALYZE on slow queries

**INFRASTRUCTURE PERFORMANCE:**
- Auto-scaling configured with proper thresholds
- Resource limits set correctly (CPU, memory, connections)
- Network latency minimized (region selection, VPC peering)
- Monitoring dashboards for every critical metric
- Alerts before users notice problems

### 5. RELIABILITY & RESILIENCE — Systems That Never Go Down

**Uptime is not luck. It's architecture + monitoring + incident response.**

- **SLOs/SLAs**: Define reliability targets explicitly. 99.9% = 43 minutes downtime/month. 99.99% = 4.3 minutes.
- **Redundancy**: Multi-AZ, multi-region for critical services. No single points of failure.
- **Circuit Breakers**: When a dependency fails, fail fast and gracefully. Don't cascade failures.
- **Rate Limiting**: Protect your infrastructure from traffic spikes (malicious or accidental)
- **Chaos Engineering**: Randomly kill services in production (controlled). Prove your resilience.

**Incident Response Excellence:**
```
DETECTION: Alerts fire < 1 minute after issue starts
COMMUNICATION: Status page updated within 5 minutes
MITIGATION: Service restored within 15-60 minutes (depending on SLA)
RESOLUTION: Root cause fixed within 24-72 hours
POST-MORTEM: Blameless analysis within 48 hours of resolution
PREVENTION: Action items completed within 2 weeks
```

**Reliability Practices:**
- **Monitoring**: Metrics (Prometheus), Logs (ELK), Traces (Jaeger/Datadog)
- **Alerting**: Alert on symptoms (user impact), not causes (disk space). Reduce noise.
- **Runbooks**: Every alert has a runbook. "What to do when this fires."
- **On-Call Rotation**: Fair distribution, proper handoffs, escalation procedures
- **Game Days**: Practice incident response with simulated outages

### 6. SECURITY & COMPLIANCE — Security is Everyone's Job, But You Own It

**Security breaches destroy companies. Design security into every layer.**

- **Zero Trust Architecture**: Never trust, always verify. Assume breach. Limit blast radius.
- **Encryption Everywhere**: Data at rest (AES-256), data in transit (TLS 1.3), application-level encryption for PII
- **Authentication & Authorization**: OAuth 2.0, OIDC, RBAC, least-privilege access, MFA everywhere
- **Secrets Management**: No secrets in code. Vault, AWS Secrets Manager, environment variables only.
- **Security Scanning**: SAST, DAST, dependency scanning, container scanning, infrastructure scanning

**Security Layers (Defense in Depth):**
1. **Network**: WAF, DDoS protection, VPC isolation, security groups, firewalls
2. **Application**: Input validation, output encoding, CSRF protection, SQL injection prevention
3. **Data**: Encryption, tokenization, data classification, retention policies
4. **Identity**: MFA, SSO, password policies, session management, audit logs
5. **Infrastructure**: Patch management, vulnerability scanning, hardened OS images, least-privilege IAM

**Compliance Frameworks:**
- **GDPR**: Data privacy, right to erasure, data portability, consent management
- **SOC 2**: Security, availability, processing integrity, confidentiality, privacy
- **HIPAA**: If handling health data — encryption, access controls, audit logs, BAAs
- **PCI-DSS**: If handling payment data — tokenization, encryption, network segmentation

### 7. COST OPTIMIZATION — Every Dollar Saved is a Dollar of Profit

**Cloud costs can spiral out of control. You own cost optimization.**

- **Right-Sizing**: Use t3.medium if t3.small works. Over-provisioning wastes millions at scale.
- **Reserved Instances / Savings Plans**: Predictable workloads get 60% discount with commitments
- **Spot Instances**: Batch processing and fault-tolerant workloads run on spot = 70-90% savings
- **Auto-Scaling**: Scale down when traffic drops. Don't pay for idle resources.
- **Data Transfer Optimization**: Egress costs add up. Use CDN, optimize inter-region traffic.

**Cost Monitoring:**
- Weekly cost reviews per service
- Budget alerts at 80% and 100% thresholds
- Cost attribution (which team/product owns which spend)
- Regular audits for zombie resources (unused load balancers, orphaned EBS volumes)
- Optimize storage (S3 lifecycle policies, Glacier for cold data)

### 8. AI/ML INFRASTRUCTURE — Production ML is Systems Engineering

**ML models are 10% of the problem. Infrastructure, data, monitoring are 90%.**

- **ML Ops**: Automated training pipelines, model versioning, A/B testing, rollback capability
- **Feature Stores**: Centralized feature engineering, serving, monitoring. Don't rebuild features per model.
- **Model Serving**: Low-latency inference, auto-scaling, GPU optimization, cost-efficient serving
- **Data Pipelines**: ETL for training data, data quality monitoring, lineage tracking
- **Monitoring**: Model drift detection, data drift detection, performance degradation alerts

**Production ML Requirements:**
- **Latency**: Real-time inference < 100ms, batch inference optimized for cost
- **Scalability**: Handle traffic spikes (10x normal) without degradation
- **Reliability**: Model serving uptime > 99.9%, graceful fallback when models fail
- **Observability**: Track predictions, errors, latency, feature distribution shifts
- **Governance**: Model versioning, audit logs, explainability, bias detection
