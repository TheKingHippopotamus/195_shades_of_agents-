# NEXUS AI — Persona API Worker

Cloudflare Worker + D1 database that serves private agent persona data
separately from the public GitHub repository.

## What this does

Exposes a read-only JSON API backed by Cloudflare D1 (SQLite). The
`<personal>` section of every agent prompt (nickname, age, about_me,
strengths, weaknesses, etc.) lives in D1 rather than in the public repo.

## Endpoints

| Method | Path | Description |
|--------|------|-------------|
| GET | `/api/health` | Liveness check |
| GET | `/api/personas` | All 195 agent personas |
| GET | `/api/personas/:agent_number` | Single agent (integer 1-195) |
| GET | `/api/personas/department/:dept_number` | All agents in a department (1-20) |

## Prerequisites

- Cloudflare account (free tier is sufficient)
- Wrangler CLI: `npm install -g wrangler`
- Node.js 18+

## Full setup sequence

### Step 1 — Authenticate wrangler

```bash
wrangler login
```

### Step 2 — Create the D1 database

```bash
wrangler d1 create nexus-personas
```

Copy the `database_id` printed in the output and paste it into
`workers/persona-api/wrangler.toml`:

```toml
[[d1_databases]]
binding       = "DB"
database_name = "nexus-personas"
database_id   = "PASTE_YOUR_ID_HERE"
```

### Step 3 — Run the schema migration

```bash
cd workers/persona-api
wrangler d1 execute nexus-personas --file=schema.sql --remote
```

### Step 4 — Extract persona data from agent .md files

Run from the repo root:

```bash
cd nexus-website
npx tsx scripts/extract-personas.ts
```

This reads all 195 `agents/*/*.md` files, parses the `<personal>` section
of each one, and writes `workers/persona-api/seed.sql`.

`seed.sql` is excluded from git via `.gitignore` — it must never be
committed to the public repository.

### Step 5 — Seed the D1 database

```bash
cd workers/persona-api
wrangler d1 execute nexus-personas --file=seed.sql --remote
```

### Step 6 — Deploy the Worker

```bash
cd workers/persona-api
wrangler deploy
```

Copy the Worker URL printed at the end (e.g.
`https://nexus-persona-api.<your-subdomain>.workers.dev`).

### Step 7 — Verify

```bash
curl https://nexus-persona-api.<your-subdomain>.workers.dev/api/health
curl https://nexus-persona-api.<your-subdomain>.workers.dev/api/personas/1
curl https://nexus-persona-api.<your-subdomain>.workers.dev/api/personas/department/2
```

## Local development

```bash
cd workers/persona-api

# Start the Worker locally (uses a local SQLite file, not the remote D1)
wrangler dev --local

# In another terminal — seed local D1
wrangler d1 execute nexus-personas --file=schema.sql --local
wrangler d1 execute nexus-personas --file=seed.sql --local

# Then hit the local Worker
curl http://localhost:8787/api/personas/1
```

## Re-seeding (after agent file updates)

When agent `<personal>` sections are updated in the .md files, re-seed:

```bash
# Regenerate seed.sql
cd nexus-website && npx tsx scripts/extract-personas.ts

# Apply to remote D1
cd ../workers/persona-api
wrangler d1 execute nexus-personas --file=seed.sql --remote
```

The `DELETE FROM agent_personas` at the top of `seed.sql` ensures the
operation is idempotent — safe to run multiple times.

## CORS

The Worker allows the following origins:

- `https://thekinghippopotamus.github.io` (production GitHub Pages)
- `http://localhost:4321` (Astro dev server)
- `http://localhost:3000` (generic local dev)

All other origins receive the production origin in the
`Access-Control-Allow-Origin` header, which browsers will block.

## Cost

- D1 reads: 5 million rows/month free, then $0.001 per million
- Worker requests: 100,000/day free, then $0.50 per million
- For 195 rows and typical traffic, this stays entirely within the free tier

## File structure

```
workers/persona-api/
  src/
    index.ts       — Worker source (TypeScript, compiled by wrangler)
  schema.sql       — D1 table definition + indexes
  seed.sql         — Generated by extract-personas.ts (NOT in git)
  wrangler.toml    — Wrangler config + D1 binding
  README.md        — This file
```

The extraction script lives in:

```
nexus-website/scripts/
  extract-personas.ts  — Reads .md files, outputs seed.sql
```
